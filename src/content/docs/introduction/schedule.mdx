This schedule shows the 10-week plan for lectures, labs, and assignments. Lectures cover the concepts needed for the upcoming lab, ideally one week in advance but at minimum by the first lecture of that lab's week.

- **Lectures:** Two 1-hour-20-minute sessions per week.
- **Labs:** Due on **Fridays** (multiple sections per week).
- **Assignments:** Due on **Sundays at 11:59 PM**, every two weeks starting in Week 2.
- **Activities:** Due at the end of the lecture week (Sunday at 11:59 PM) for the week they are assigned. They are done in class.

<Aside type="caution">
This schedule is subject to change. Always check Canvas for the most up-to-date due dates.
</Aside>

## Week 1: Hardware and Virtualization

| | |
|---|---|
| **Lecture 1** | [Hardware Fundamentals](/lectures/hardware-fundamentals/) |
| **Lecture 2** | [Virtualization and Virtual Machines](/lectures/virtualization-basics/) |
| **Lab 1a** | [The Bare Metal](/labs/the-bare-metal/) |
| **Lab 1b** | [Cloud Environment Setup (AWS Academy)](/labs/cloud-environment-setup/) |

Hardware Fundamentals supports the Bare Metal lab. Virtualization is introduced this week so you understand what a virtual machine is before spinning one up in Lab 1b: an EC2 instance is a VM running on AWS's infrastructure.

## Week 2: Linux and Networking

| | |
|---|---|
| **Lecture 3** | [Linux Server Planning and Configuration](/lectures/linux-server-planning-and-configuration/) |

| **Assignment 1** | **Sunday: [Ops 1: Manual Minecraft Server](/assignments/minecraft-1-manual-server/)** |

Linux Server Planning prepares you for the hands-on WordPress deployment this week. Networking Fundamentals supports the VPC and security group configuration in the same lab.

## Week 3: Containers and Cloud Services

| | |
|---|---|
| **Lecture 5** | Containerization with Docker |
| **Lecture 6** | Cloud Computing and VM Deployment |
| **Lab 3** | [Containerizing a Web Application (Docker Compose)](/labs/containerizing-a-web-application/) |

Docker builds directly on the VM foundation from Week 1: containers share a kernel instead of virtualizing hardware. Cloud Computing is introduced Thursday to cover S3, ECR, IAM roles, and VPC design one full week before you use ECR and S3 in Lab 4.

| | |
|---|---|
| **Lecture 7** | System Security and Hardening |
| **Lecture 8** | Shell Scripting and Automation Basics |
| **Lab 4** | [Image Registry, Backups, and Version Switching (ECR + S3)](/labs/image-registry-and-version-switching/) |
| **Assignment 2** | **Sunday: [Ops 2: Containerized Minecraft Server](/assignments/minecraft-2-containerized-server/)** |

Security hardening covers IAM policies and access controls that apply directly to the ECR and S3 work in this week's lab. Scripting supports the backup and versioning workflows here and the automation-heavy weeks ahead.

| **Lecture 9** | Network Configuration and Troubleshooting |
| **Lecture 10** | Infrastructure as Code with Terraform |

Network troubleshooting deepens your ability to debug VPC and connectivity issues you will encounter as your infrastructure grows. Terraform is introduced Thursday, giving you the concepts immediately before the hands-on lab.

| | |
|---|---|
| **Lecture 11** | Configuration Management with Ansible |
| **Lecture 12** | CI/CD Pipelines and GitHub Actions |
| **Lab 6** | [Automated Configuration and Deployment (Ansible + GitHub Actions)](/labs/automated-configuration-and-deployment/) |
| **Assignment 3** | **Sunday: [Ops 3: Infrastructure Automation](/assignments/minecraft-3-infrastructure-automation/)** |

Both lectures directly support this week's lab. Ansible covers idempotent configuration; CI/CD covers the automated build-test-deploy pipeline you will build with GitHub Actions.

## Week 7: Container Orchestration and Logging

| | |
|---|---|
| **Lecture 13** | Container Orchestration with Kubernetes |
| **Lecture 14** | Log Management and Analysis |
| **Lab 7** | [First Container Orchestration Deployment (k3s)](/labs/first-container-orchestration-deployment/) |

Kubernetes introduces the orchestration concepts directly before the k3s lab. Log Management is paired here because you will need log analysis skills immediately when debugging pod deployments — `kubectl logs`, container crash output, and event streams are the first tools you reach for when something fails in a cluster.

## Week 8: Incident Response and Monitoring

| | |
|---|---|
| **Lecture 15** | Incident Response and Disaster Recovery |
| **Lecture 16** | Monitoring and Performance Management |
| **Lab 8** | [Cluster Operations: Health Probes, Rollouts, and Failure Drills (Kubernetes)](/labs/cluster-operations/) |
| **Assignment 4** | **Sunday: [Ops 4: Container Orchestration](/assignments/minecraft-4-container-orchestration/)** |

Incident Response is moved here because Lab 8's failure drills — bad images, OOM kills, rollbacks — are the exact scenarios the lecture prepares you for. RTO/RPO concepts now have direct hands-on context. Monitoring covers health probes, resource metrics, and alerting patterns that this week's lab configures and that next week's observability workshop builds on.

## Week 9: Postmortems and Server Breadth

| | |
|---|---|
| **Lecture 17** | Postmortems and Communications |
| **Lecture 18** | Windows Server Administration and Active Directory |
| **Lab 9** | [Observability Workshop: Metrics and Dashboards (Prometheus + Grafana)](/labs/observability-workshop/) |

The observability lab builds on the monitoring concepts from Week 8. Postmortems is paired here — one week before Assignment 5's postmortem requirement — so the blameless review framework and communication templates are fresh when you sit down to write. Windows Server broadens your perspective: the same administration principles apply outside Linux.

## Week 10: Architecture and Wrap-Up

| | |
|---|---|
| **Lecture 19** | Server and Data Center Architecture |
| **Lecture 20** | Documentation, Teamwork, and Course Wrap-Up |
| **Lab 10** | Make-up lab (catch up on incomplete lab work) |
| **Assignment 5** | **Sunday: [Ops 5: Observability and Incident Response](/assignments/minecraft-5-observability/)** |

Server and Data Center Architecture works as a capstone breadth lecture: you now have the full-stack context — from containers to clusters to cloud — to understand server hardware, storage hierarchies, and physical infrastructure at a meaningful level. The course wrap-up follows.

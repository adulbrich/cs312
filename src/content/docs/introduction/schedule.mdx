This schedule shows the 10-week plan for lectures, labs, and assignments. Lectures cover the concepts needed for the upcoming lab, ideally one week in advance but at minimum by the first lecture of that lab's week.

- **Lectures:** Two 1-hour-20-minute sessions per week.
- **Labs:** Due on **Fridays** (multiple sections per week).
- **Assignments:** Due on **Sundays at 11:59 PM**, every two weeks starting in Week 2.
- **Activities:** Due at the end of the lecture week (Sunday at 11:59 PM) for the week they are assigned. They are done in class.

<Aside type="caution">
This schedule is subject to change. Always check Canvas for the most up-to-date due dates.
</Aside>

| | |
|---|---|

Hardware Fundamentals supports the Bare Metal lab. Virtualization is introduced this week so you understand what a virtual machine is before spinning one up in Lab 1b: an EC2 instance is a VM running on AWS's infrastructure.

| | |

## Week 3: Containers and Cloud Services

| | |
|---|---|
| **Lecture 5** | [Containerization](/lectures/containerization-with-docker/) |

Docker builds directly on the VM foundation from Week 1: containers share a kernel instead of virtualizing hardware. Cloud Networking, Storage, and Identity is introduced Thursday to cover VPC design, IAM roles, S3, and ECR one full week before you use ECR and S3 in Lab 4.

## Week 5: Configuration Management and CI/CD

| | |
|---|---|
| **Lecture 9** | [Configuration Management](/lectures/configuration-management/) |
| **Lecture 10** | [CI/CD Pipelines](/lectures/ci-cd/) |
| **Lab 5** | [Your First Infrastructure Stack (Terraform)](/labs/first-infrastructure-stack/) |

Both lectures directly prepare you for Lab 6 the following week, giving you a full week to absorb Ansible and GitHub Actions before building the automated pipeline. The Terraform infrastructure from Lab 5 is exactly what Ansible and CI/CD will configure and deploy to in Lab 6.

## Week 6: Kubernetes and Network Infrastructure

| | |
|---|---|
| **Lecture 11** | [Container Orchestration](/lectures/container-orchestration/) |
| **Lecture 12** | [Network Services and Application Delivery](/lectures/network-services-and-application-delivery/) |
| **Lab 6** | [Automated Configuration and Deployment (Ansible + GitHub Actions)](/labs/automated-configuration-and-deployment/) |
| **Assignment 3** | **Sunday: [Ops 3: Infrastructure Automation](/assignments/minecraft-3-infrastructure-automation/)** |

Container Orchestration is introduced a full week and a half before Lab 7's k3s deployment so the orchestration concepts have time to settle before you apply them. The Network Services and Application Delivery lecture follows immediately: reverse proxies, load balancers, DNS, TLS, and overlay versus underlay networking are the infrastructure layer that Kubernetes clusters sit on. Covering them together makes the connection between Ingress controllers and ordinary reverse proxies, and between CNI overlays and physical network topology, concrete rather than abstract.

## Week 7: Security and Observability

| | |
|---|---|
| **Lecture 13** | System Security and Hardening |
| **Lecture 14** | Monitoring, Alerting, and Observability |
| **Lab 7** | [First Container Orchestration Deployment (k3s)](/labs/first-container-orchestration-deployment/) |

System Security and Hardening revisits Linux, networking, containers, cloud, IaC, configuration management, and CI/CD through a security lens, and extends forward to cluster security concerns (RBAC, secrets, network policies) that Lab 7 will begin to surface. Monitoring, Alerting, and Observability lands the same week, one week before Lab 8's health-probe work, so metrics, SLOs, and alert design concepts are fresh when you need them.

## Week 8: Incident Response and Log Diagnostics

| | |
|---|---|
| **Lecture 15** | Incident Response and Disaster Recovery |
| **Lecture 16** | Log Management and Incident Investigation |
| **Lab 8** | [Cluster Operations: Health Probes, Rollouts, and Failure Drills (Kubernetes)](/labs/cluster-operations/) |
| **Assignment 4** | **Sunday: [Ops 4: Container Orchestration](/assignments/minecraft-4-container-orchestration/)** |

Incident Response covers the lifecycle and mitigation commands you need directly during Lab 8's failure drills: rollback, cordon, drain, and port-forward are the tools you reach for when a deployment goes wrong. Log Management pairs with the same lab: when a pod crashes or a rollout fails, logs are the first diagnostic tool you reach for, and the structured investigation method from this lecture applies immediately.

## Week 9: Reliability and Server Breadth

| | |
|---|---|
| **Lecture 17** | Site Reliability Engineering and Capacity Planning |
| **Lecture 18** | Windows Server Administration |
| **Lab 9** | [Observability Workshop: Metrics and Dashboards (Prometheus + Grafana)](/labs/observability-workshop/) |

Site Reliability Engineering lands alongside Lab 9 deliberately: students who have just deployed a Prometheus stack and written alert rules can immediately connect error budgets, toil, and on-call sustainability to systems they have operated. Assignment 5's postmortem requirement is two weeks away, and the SRE framing gives the blameless-postmortem concept an organizational home rather than presenting it as an isolated ritual. Windows Server broadens your perspective: the same administration and reliability principles apply outside Linux.

## Week 10: Architecture and Wrap-Up

| | |
|---|---|
| **Lecture 19** | On-Premises Infrastructure and Data Center Architecture |
| **Lecture 20** | Documentation, Teamwork, and Course Wrap-Up |
| **Lab 10** | Make-up lab (catch up on incomplete lab work) |
| **Assignment 5** | **Sunday: [Ops 5: Observability and Incident Response](/assignments/minecraft-5-observability/)** |

On-Premises Infrastructure and Data Center Architecture covers the physical layer beneath cloud and container abstractions: hierarchical network design, VLANs, enterprise routing, server hardware platforms, storage technologies, and data center design. The course wrap-up follows.

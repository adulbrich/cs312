This activity puts into practice the concepts from the [Linux Server Planning and Configuration](/lectures/linux-server-planning-and-configuration/) lecture. Where Debian's installer handles partitioning, bootloader installation, user creation, and networking automatically, Arch Linux makes you do each step by hand. That is precisely the point: by the end of this exercise, you will have directly touched every layer of a Linux system that most distributions hide behind a setup wizard.

## What You Will Need

- A laptop with a hypervisor installed (VirtualBox, UTM, or similar)
- The Arch Linux ISO image:

<Tabs syncKey="arch">
<TabItem label="x86_64 (Intel/AMD)">
Download the latest x86_64 ISO from [release.archboot.com/x86_64/latest/iso/](https://release.archboot.com/x86_64/latest/iso/). Pick the ISO labelled `latest`.
</TabItem>
<TabItem label="aarch64 (Apple Silicon / ARM)">
Download the latest aarch64 ISO from [release.archboot.com/aarch64/latest/iso/](https://release.archboot.com/aarch64/latest/iso/). Pick the ISO labelled `latest`. 
</TabItem>
</Tabs>

- About 2 GB of free disk space for the VM
- An internet connection

## Create the Virtual Machine

In your hypervisor of choice (VirtualBox, UTM, VNWare, etc.), create a new VM with the following settings:

- Memory: 4096 MB
- CPU: 2 cores
- Disk: 8 GB, dynamically allocated
- Network: NAT (default)
- Optical drive: attach the Arch Linux ISO you downloaded above, matching your architecture (x86_64 or aarch64)
- Make sure you use (U)EFI firmware, not legacy BIOS. This is required for the EFI System Partition we will create.

## Boot into the Live Environment

<Steps>
1. Start the VM. The archboot ISO boots into a setup menu rather than dropping straight to a shell. When you see the menu, press **Ctrl+C** to exit it and reach the root shell prompt.

2. Verify you have an internet connection (the VM's NAT adapter piggybacks on your host's network):

   ```bash
   ping -c 3 archlinux.org
   ```

   If this fails, verify that the VM's network adapter is enabled and set to NAT.

3. Update the package database and install the partitioning tool:

   ```bash
   pacman -Sy gptfdisk
   ```

   `gdisk` is not included in the live environment by default. This step fetches it from the Arch mirrors before you need it.

4. Identify the name of your virtual disk:

   ```bash
   lsblk
   ```

   Look for a disk-type device (TYPE=`disk`) with roughly 8 GB of space. On VirtualBox it is typically `/dev/sda`; on UTM it is typically `/dev/vda`. The steps below use tabs to show the correct device name for each.
</Steps>

<Aside type="note" title="About the live environment">
You are currently running from a RAM-based live environment. Nothing you do here persists to disk until you explicitly install it. The live environment is your staging area.
</Aside>

## Partition the Disk

We will create three partitions using GPT: an EFI System Partition, a swap partition, and a root partition.

<Steps>
1. Launch the partitioning tool:

   ```bash
   # replace sda with your disk name if different
   gdisk /dev/sda 
   ```

   <Aside type="tip" title="Made a mistake?">
   If you make a mistake at any point, type `o` at the gdisk prompt to wipe the partition table and start over. Changes are not written to disk until you explicitly tell gdisk to do so.
   </Aside>

2. **Create the EFI System Partition.** Type `n` for a new partition. Accept the default partition number (1) and default first sector. For the last sector, type `+300M`. When prompted for the hex code, enter `ef00` (EFI System Partition).

   ```
   Command (? for help): n
   Partition number (1-128, default 1):
   First sector (34-16777182, default = 2048) or {+-}size{KMGTP}:
   Last sector (...) or {+-}size{KMGTP}: +300M
   Hex code or GUID (L to show codes, Enter = 8300): ef00
   ```

3. **Create the swap partition.** Type `n` again. Accept defaults for partition number (2) and first sector. For the last sector, type `+400M`. Hex code: `8200` (Linux swap).

4. **Create the root partition.** Type `n` again. Accept all defaults (partition 3, default first sector, default last sector to use all remaining space). Accept the default hex code `8300` (Linux filesystem).

5. **Verify your work.** Type `p` to print the partition table. You should see something like:

   ```
   Number  Start (sector)    End (sector)  Size       Code  Name
      1            2048          616447   300.0 MiB   EF00  EFI system partition
      2          616448         1435647   400.0 MiB   8200  Linux swap
      3         1435648        16777182   7.3 GiB     8300  Linux filesystem
   ```

6. **Write the partition table.** Type `w` and confirm with `Y`.
</Steps>

### Format the Partitions

Each partition needs a filesystem before it can hold data. This is what `mkfs` does, and it is the same concept as the `mkfs.ext4` example from the lecture's disk management section.

```bash
# FAT32 on the EFI partition (required by the UEFI specification)
mkfs.fat -F32 /dev/sda1

# ext4 on the root partition
mkfs.ext4 -F /dev/sda3

# Initialize and activate swap
mkswap /dev/sda2
swapon /dev/sda2
```

### Mount the Filesystems

```bash
# Mount the root partition
mount /dev/sda3 /mnt

# Create and mount the EFI partition
mkdir -p /mnt/boot/efi
mount /dev/sda1 /mnt/boot/efi
```

<Aside type="note" title="Checkpoint">
Run `lsblk` and verify that your root partition is mounted at `/mnt` and your EFI partition at `/mnt/boot/efi`.
</Aside>

## Install the Base System

This step downloads and installs the core Arch Linux packages into your mounted root partition. The `pacstrap` tool is Arch's equivalent of running an installer, but it is transparent: you can see exactly which packages it installs.

```bash
pacstrap /mnt base linux vim
```

This installs about 120 packages including the Linux kernel itself. It will take a few minutes depending on your internet speed.

While it runs, generate the filesystem table so the installed system knows how to mount its own partitions at boot:

```bash
genfstab -U /mnt > /mnt/etc/fstab
```

## Enter the New System

To configure the installed system, you need to "pivot" into it using `chroot` (change root). This makes `/mnt` appear as `/` so that every command you run applies to the installed system, not the live environment.

```bash
arch-chroot /mnt
```

Verify you are inside the chroot:

```bash
pwd
# Should output: /
```

## Configure Locale and Timezone

<Steps>
1. Set the timezone (adjust if you are not on the US West Coast):

   ```bash
   cp /usr/share/zoneinfo/America/Los_Angeles /etc/localtime
   date
   ```

2. Configure the locale. Open the locale configuration file:

   ```bash
   vim /etc/locale.gen
   ```

   Find and uncomment these two lines (remove the leading `#`):

   ```
   en_US.UTF-8 UTF-8
   en_US ISO-8859-1
   ```

3. Generate the locale and set it as default:

   ```bash
   locale-gen
   echo LANG=en_US.UTF-8 > /etc/locale.conf
   export LANG=en_US.UTF-8
   ```
</Steps>

## Install the Bootloader

<Steps>
1. Install GRUB and supporting EFI tools:

   ```bash
   pacman -S grub efibootmgr dosfstools mtools
   ```

2. Install GRUB to the EFI partition:

   <Tabs syncKey="arch">
   <TabItem label="x86_64 (Intel/AMD)">
   ```bash
   grub-install --target=x86_64-efi --bootloader-id=arch --recheck
   ```
   </TabItem>
   <TabItem label="aarch64 (Apple Silicon / ARM)">
   ```bash
   grub-install --target=arm64-efi --bootloader-id=arch --removable --recheck
   ```
   The `--removable` flag installs the bootloader to the fallback EFI path (`/boot/efi/EFI/BOOT/BOOTAA64.EFI`), which UTM's firmware looks for when no specific boot entry is registered.
   </TabItem>
   </Tabs>

3. Generate the GRUB configuration:

   ```bash
   grub-mkconfig -o /boot/grub/grub.cfg
   ```
</Steps>

## Configure sudo and Create a User

<Steps>
1. Install sudo:

   ```bash
   pacman -S sudo
   ```

2. Open the sudoers file (never edit it directly, always use `visudo`):

   ```bash
   visudo
   ```

   Find and uncomment this line:

   ```
   %wheel ALL=(ALL) ALL
   ```

   This grants sudo access to all members of the `wheel` group, the same concept as Ubuntu's `sudo` group that the lecture describes.

3. Create a regular user with a home directory, bash shell, and wheel group membership:

   ```bash
   useradd -m -G wheel -s /bin/bash archuser
   ```

4. Set the password:

   ```bash
   passwd archuser
   ```
</Steps>

<ActivityQuestion>
The lecture warns that forgetting the `-a` flag with `usermod -aG` replaces all supplementary groups. Why did we not need `-a` here when we used `useradd -G wheel` to create the user?
</ActivityQuestion>

## Reboot into Your New System

<Steps>
1. Exit the chroot:

   ```bash
   exit
   ```

2. Eject the ISO from the VM's virtual optical drive (use your hypervisor's UI).

3. Reboot:

   ```bash
   reboot
   ```
</Steps>

After a few seconds, GRUB should appear, select Arch Linux, and drop you at a login prompt. Log in as `archuser` with the password you set.

<Aside type="caution" title="Boot warnings are normal">
You may see warnings during boot. This is normal for a minimal Arch installation. Let the boot sequence complete on its own.
</Aside>

## Configure Networking

<Steps>
1. Set a hostname (the lecture covers this with `hostnamectl`):

   ```bash
   sudo vim /etc/hostname
   ```

   Type a single word (e.g., `archbox`) and save the file.

2. Configure `/etc/hosts`:

   ```bash
   sudo vim /etc/hosts
   ```

   Add these lines:

   ```
   127.0.0.1   localhost
   127.0.1.1   archbox.localdomain archbox
   ```

3. Find your network interface name:

   ```bash
   ip link
   ```

   You will see `lo` (loopback) and one other interface, likely `enp0s3` or similar. Note the name.

4. Create a systemd-networkd configuration file:

   ```bash
   sudo vim /etc/systemd/network/20-wired.network
   ```

   Add the following (substitute your interface name if it differs):

   ```ini
   [Match]
   Name=enp0s3

   [Network]
   DHCP=yes
   ```

5. Enable and start the network service:

   ```bash
   sudo systemctl enable --now systemd-networkd
   ```

6. Verify you received an IP address:

   ```bash
   ip addr show
   ```

   Look for an `inet` address on your interface (e.g., `10.0.2.15/24`).

7. Configure DNS so you can resolve domain names:

   ```bash
   sudo vim /etc/resolv.conf
   ```

   Add:

   ```
   nameserver 8.8.8.8
   nameserver 8.8.4.4
   ```

8. Test your connection:

   ```bash
   ping -c 3 archlinux.org
   ```
</Steps>

## Set Up SSH Key Authentication

<Steps>
1. Install the OpenSSH server:

   ```bash
   sudo pacman -S openssh
   ```

2. Enable and start the SSH daemon:

   ```bash
   sudo systemctl enable --now sshd
   ```

3. Generate a key pair as `archuser` (not root):

   ```bash
   ssh-keygen -t ed25519 -C "archuser practice key"
   ```

   Accept the default path (`~/.ssh/id_ed25519`). You can set a passphrase or leave it empty for this exercise. Two files are created:
   - `~/.ssh/id_ed25519`: the **private key**. Never share or copy this to another machine.
   - `~/.ssh/id_ed25519.pub`: the **public key**. Safe to copy anywhere.

4. Install the public key into `authorized_keys`:

   ```bash
   mkdir -p ~/.ssh
   chmod 700 ~/.ssh
   cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

   The permissions are enforced by SSH itself: if `~/.ssh` or `authorized_keys` are group- or world-writable, SSH will refuse to use them.

5. Test key authentication by connecting to localhost:

   ```bash
   ssh -i ~/.ssh/id_ed25519 archuser@localhost
   ```

   You should receive a shell prompt without entering a password. Type `exit` to return.

6. Locate the password authentication setting:

   ```bash
   grep PasswordAuthentication /etc/ssh/sshd_config
   ```

   On a production server exposed to the internet you would set this to `no` after confirming key auth works. Do not change it here; you are on a local VM with no remote exposure.
</Steps>

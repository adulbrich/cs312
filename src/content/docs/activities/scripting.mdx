This activity puts into practice the concepts from the [Shell Scripting and Automation Basics](/lectures/shell-scripting-and-automation-basics/) lecture. You will build a log analysis script incrementally, adding one concept at a time until you have a complete, production-style tool. By the end, you will have a working script that accepts arguments, searches log files for error patterns using regular expressions, loops over multiple files, formats a report, and exits with meaningful status codes.

## What You Will Need

You need a Bash shell and standard Unix tools (`grep`, `sed`, `find`, `date`). All of these are available on macOS and Linux with no installation required. Windows users will use Git Bash.

<Tabs syncKey="os">
<TabItem label="macOS">
macOS ships with Bash at `/bin/bash` (version 3.2). Open Terminal from Applications and verify:

```bash
bash --version
```

You should see something like `GNU bash, version 3.2.57`. All commands in this activity are compatible with Bash 3.2.

<Aside type="tip" title="Running bash from zsh">
macOS defaults to zsh as the interactive shell since Catalina, but Bash is still installed. Your scripts use `#!/usr/bin/env bash` in the shebang, so they always run under Bash regardless of which shell you are typing in.
</Aside>
</TabItem>

If your system does not have `grep` or `sed`, install them with your package manager:

```bash
sudo pacman -S grep sed
```
</TabItem>
<TabItem label="Windows">

## Your First Script

Create the script file, add the shebang and safe defaults, and verify that the safety mechanisms actually work before building on top of them.

The script you are building is called `logscan.sh`. You will add to it in each section.

<Steps>
1. Create the script file:

   ```bash
   touch logscan.sh
   chmod +x logscan.sh
   ```

   `chmod +x` sets the execute permission bit. Without it, the kernel refuses to run the file directly. You can always run a script with `bash logscan.sh` to bypass this, but setting the execute bit is the conventional approach.

2. Open `logscan.sh` in any text editor and add the following:

   ```bash
   #!/usr/bin/env bash
   set -euo pipefail

   echo "logscan starting"
   echo "done"
   ```

3. Run the script:

   ```bash
   ./logscan.sh
   ```

   You should see:
   ```
   logscan starting
   done
   ```

4. See `set -e` in action by adding a bad command. Edit the script and insert a line between the two `echo` statements:

   ```bash
   #!/usr/bin/env bash
   set -euo pipefail

   echo "logscan starting"

   ```

   Run it:

   ```bash
   ./logscan.sh
   ```

   You will see `logscan starting` and then the error from `ls`, but you will **not** see `done`. The script stopped at the failing command. Remove the bad `ls` line before continuing.
</Steps>

## Variables and Arguments

Add argument handling and variables to the script. By the end of this section, the script will validate its input and refuse to run if it is wrong.

<Steps>
1. Replace the contents of `logscan.sh` with:

   ```bash
   #!/usr/bin/env bash
   set -euo pipefail

   if [[ "$#" -ne 1 ]]; then
       printf "Usage: %s <log-directory>\n" "$(basename "$0")" >&2
       exit 1
   fi

   LOG_DIR="$1"

   if [[ ! -d "$LOG_DIR" ]]; then
       printf "Error: '%s' is not a directory\n" "$LOG_DIR" >&2
       exit 1
   fi

   TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
   REPORT_USER=$(whoami)
   REPORT_HOST=$(hostname)

   printf "=== Log Report: %s ===\n" "$REPORT_HOST"
   printf "Generated: %s by %s\n" "$TIMESTAMP" "$REPORT_USER"
   printf "Log directory: %s\n\n" "$LOG_DIR"
   ```

2. Run it without arguments to see the usage message:

   ```bash
   ./logscan.sh
   ```

   You should see:
   ```
   Usage: logscan.sh <log-directory>
   ```

3. Run it with a directory that does not exist:

   ```bash
   ./logscan.sh /nonexistent
   ```

   You should see:
   ```
   Error: '/nonexistent' is not a directory
   ```

4. Run it with the real log directory:

   ```bash
   ./logscan.sh logs
   ```

   You should see a header with your hostname, the current timestamp, and your username.
</Steps>

## Searching with grep and Regular Expressions

This section adds log searching to the script. You will search the log files using regular expressions, then add the search to the script itself.

First, practice searching directly in the terminal before adding anything to the script.

<Steps>
1. Count how many ERROR lines are in each log file:

   ```bash
   grep -c "ERROR" logs/web.log
   grep -c "ERROR" logs/db.log
   grep -c "ERROR" logs/system.log
   ```

   `grep -c` counts matching lines rather than printing them.

2. Search for any line containing either ERROR or WARN using extended regular expressions:

   ```bash
   grep -E "ERROR|WARN" logs/web.log
   ```

   The `|` operator is alternation: it matches lines containing either string. Without `-E`, you would need to escape it as `\|` in basic RE syntax.

3. Search for lines where ERROR or WARN appears at a specific position using anchoring. The timestamp format in your logs is always `YYYY-MM-DD HH:MM:SS`, followed by a space, then the level. Anchor the level to position 20:

   ```bash
   grep -E "^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2} ERROR" logs/web.log
   ```

   Breaking this pattern down:
   - `^` anchors the match to the beginning of the line
   - `[0-9]{4}` matches exactly four digits
   - `-` matches a literal hyphen
   - `[0-9]{2}` matches exactly two digits
   - The space and colon characters match literally

4. Show only the lines that do **not** contain INFO:

   ```bash
   grep -v "INFO" logs/web.log
   ```

   `-v` inverts the match: every line that does **not** contain the pattern.

5. Search recursively across all log files at once and show file names:

   ```bash
   grep -rn "ERROR" logs/
   ```

   `-r` recurses into subdirectories, `-n` prepends line numbers. When searching multiple files, `grep` prepends the filename to each matching line automatically.

6. Find all lines mentioning an IP address using a regular expression:

   ```bash
   grep -E "([0-9]{1,3}\.){3}[0-9]{1,3}" logs/system.log
   ```

   `{1,3}` means "one to three occurrences." The `\.` escapes the dot so it matches a literal period rather than any character.
</Steps>

<ActivityQuestion>
Your regex `([0-9]{1,3}\.){3}[0-9]{1,3}` matches IP addresses in the log, but it would also match strings like `999.999.999.999` which is not a valid IP address. Why is this acceptable in log searching, and in what situation would you need a stricter pattern?
</ActivityQuestion>

## Functions, Loops, and Formatted Output

Now integrate the search into the script using a function and a loop. The function scans one file and returns counts; the loop calls it for every log file in the directory.

<Steps>
1. Add a `scan_file` function to your script. Place it after the header-printing lines:

   ```bash
   scan_file() {
       local file="$1"
       local name
       name=$(basename "$file")
       local errors
       errors=$(grep -Ec "ERROR" "$file" 2>/dev/null || true)
       local warnings
       warnings=$(grep -Ec "WARN" "$file" 2>/dev/null || true)
       printf "  %-30s  errors: %-4s  warnings: %s\n" "$name" "$errors" "$warnings"
   }
   ```

   Three things to notice here. First, every variable is declared with `local`, which restricts its scope to the function. Without `local`, `name`, `errors`, and `warnings` would be global and could collide with variables in other functions or the main script body. Second, `grep -c` exits with status 1 when there are zero matches, which would cause the script to abort under `set -e`. The `|| true` appended after each `grep` call prevents that: if grep finds nothing and returns 1, `true` runs instead and returns 0, keeping the script alive. Third, `2>/dev/null` discards any error messages from `grep` itself (for example, if the file is unreadable).

2. Add the loop below the function definition. This goes after the function but before the end of the script:

   ```bash
   TOTAL_ERRORS=0
   TOTAL_WARNINGS=0
   FILE_COUNT=0

   for logfile in "$LOG_DIR"/*.log; do
       [[ -f "$logfile" ]] || continue
       scan_file "$logfile"
       errors=$(grep -Ec "ERROR" "$logfile" 2>/dev/null || true)
       warnings=$(grep -Ec "WARN" "$logfile" 2>/dev/null || true)
       TOTAL_ERRORS=$(( TOTAL_ERRORS + errors ))
       TOTAL_WARNINGS=$(( TOTAL_WARNINGS + warnings ))
       (( FILE_COUNT++ )) || true
   done
   ```

   The pattern `[[ -f "$logfile" ]] || continue` handles the edge case where the glob `*.log` matches nothing: if the directory contains no `.log` files, Bash expands the glob to the literal string `logs/*.log`, which is not a real file. The check skips it rather than failing.

3. Add a summary block after the loop:

   ```bash
   printf "\nSummary: %d file(s)  |  %d error(s)  |  %d warning(s)\n" \
       "$FILE_COUNT" "$TOTAL_ERRORS" "$TOTAL_WARNINGS"
   ```

4. Run the script now:

   ```bash
   ./logscan.sh logs
   ```

   You should see a formatted table with a line per log file and a summary at the bottom.

5. Add a `sed` substitution to clean up error messages before displaying them. Append this block after the summary:

   ```bash
   if [[ "$TOTAL_ERRORS" -gt 0 ]]; then
       printf "\nDistinct errors:\n"
       grep -h "ERROR" "$LOG_DIR"/*.log 2>/dev/null \
           | sed 's/^[0-9-]* [0-9:]* [A-Z]*  //' \
           | sort -u
   fi
   ```

   `grep -h` suppresses filename prefixes in the output. The `sed` substitution strips the leading timestamp and log level from each line, leaving only the service name and message. The pattern `^[0-9-]* [0-9:]* [A-Z]*  ` matches the timestamp, a space, the log level, and two trailing spaces at the start of each line. `sort -u` removes duplicate messages so each unique error appears once.

6. Run the script again:

   ```bash
   ./logscan.sh logs
   ```

   The distinct error messages should now appear at the bottom, deduplicated and without timestamps.
</Steps>

## Your Log Report

Add the finishing touches: a clean exit code and a `trap` for cleanup. Then run the complete script and review the output.

<Steps>
1. Add an exit code at the very end of the script. If there were any errors in the logs, exit with status 1 so that callers (including cron) can detect a problem:

   ```bash
   if [[ "$TOTAL_ERRORS" -gt 0 ]]; then
       exit 1
   fi
   ```

2. Add a `trap` near the top of the script, right after `set -euo pipefail`. It will clean up a temporary file that you may add later without having to remember to delete it manually:

   ```bash
   TMPFILE=$(mktemp)
   trap 'rm -f "$TMPFILE"' EXIT
   ```

   `mktemp` creates a uniquely named temporary file. `trap ... EXIT` fires the cleanup command whenever the script exits, whether it succeeds, fails, or is interrupted by Ctrl+C. This is the Bash equivalent of a `finally` block.

   You are not actually using `$TMPFILE` yet, but the pattern is worth seeing in place: the trap is set up before any work begins, so there is no window where the temporary file could be left behind.

3. Your complete `logscan.sh` should now look like this:

   ```bash
   #!/usr/bin/env bash
   set -euo pipefail

   TMPFILE=$(mktemp)
   trap 'rm -f "$TMPFILE"' EXIT

   if [[ "$#" -ne 1 ]]; then
       printf "Usage: %s <log-directory>\n" "$(basename "$0")" >&2
       exit 1
   fi

   LOG_DIR="$1"

   if [[ ! -d "$LOG_DIR" ]]; then
       printf "Error: '%s' is not a directory\n" "$LOG_DIR" >&2
       exit 1
   fi

   TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
   REPORT_USER=$(whoami)
   REPORT_HOST=$(hostname)

   printf "=== Log Report: %s ===\n" "$REPORT_HOST"
   printf "Generated: %s by %s\n" "$TIMESTAMP" "$REPORT_USER"
   printf "Log directory: %s\n\n" "$LOG_DIR"

   scan_file() {
       local file="$1"
       local name
       name=$(basename "$file")
       local errors
       errors=$(grep -Ec "ERROR" "$file" 2>/dev/null || true)
       local warnings
       warnings=$(grep -Ec "WARN" "$file" 2>/dev/null || true)
       printf "  %-30s  errors: %-4s  warnings: %s\n" "$name" "$errors" "$warnings"
   }

   TOTAL_ERRORS=0
   TOTAL_WARNINGS=0
   FILE_COUNT=0

   for logfile in "$LOG_DIR"/*.log; do
       [[ -f "$logfile" ]] || continue
       scan_file "$logfile"
       errors=$(grep -Ec "ERROR" "$logfile" 2>/dev/null || true)
       warnings=$(grep -Ec "WARN" "$logfile" 2>/dev/null || true)
       TOTAL_ERRORS=$(( TOTAL_ERRORS + errors ))
       TOTAL_WARNINGS=$(( TOTAL_WARNINGS + warnings ))
       (( FILE_COUNT++ )) || true
   done

   printf "\nSummary: %d file(s)  |  %d error(s)  |  %d warning(s)\n" \
       "$FILE_COUNT" "$TOTAL_ERRORS" "$TOTAL_WARNINGS"

   if [[ "$TOTAL_ERRORS" -gt 0 ]]; then
       printf "\nDistinct errors:\n"
       grep -h "ERROR" "$LOG_DIR"/*.log 2>/dev/null \
           | sed 's/^[0-9-]* [0-9:]* [A-Z]*  //' \
           | sort -u
   fi

   if [[ "$TOTAL_ERRORS" -gt 0 ]]; then
       exit 1
   fi
   ```

4. Run the completed script:

   ```bash
   ./logscan.sh logs
   ```

   Your output should look similar to:

   ```
   === Log Report: your-hostname ===
   Generated: 2026-04-14 10:30:00 by your-username
   Log directory: logs

     db.log                          errors: 2     warnings: 1
     system.log                      errors: 0     warnings: 2
     web.log                         errors: 3     warnings: 1

   Summary: 3 file(s)  |  5 error(s)  |  4 warning(s)

   Distinct errors:
   mysql: Can't connect to MySQL server on '10.0.1.9' (111)
   mysql: Disk is full writing '/var/lib/mysql/ib_logfile0'
   nginx: no live upstreams while connecting to upstream
   nginx: upstream connect error (111: Connection refused)
   nginx: upstream timed out (110: Connection timed out)
   ```

   Your hostname and username appear in the second line. The distinct errors are alphabetically sorted because `sort -u` sorts as well as deduplicates.

5. Check the exit code:

   ```bash
   echo "Exit code: $?"
   ```

   Because the logs contain errors, the exit code is `1`. Now create an empty directory with no errors and run against it to see exit code `0`:

   ```bash
   mkdir logs/empty
   ./logscan.sh logs/empty
   echo "Exit code: $?"
   ```
</Steps>

## Going Further

Your script covers the core concepts from the lecture. Two natural directions to continue:

**Schedule it with cron.** Add your script to the crontab with `crontab -e` and schedule it to run every morning:

```
0  7  *  *  *  /home/youruser/scripts/logscan.sh /var/log >> /tmp/logscan-report.txt 2>&1
```

This runs at 7:00 AM every day, appending both stdout and stderr to a report file. Run `crontab -l` to verify the entry was saved. On a Linux server (your EC2 instance or Arch VM), cron will be running and will fire the job at the scheduled time.

**Add interactive mode with `select`.** The `select` built-in generates a numbered menu. Try extending the script to let the user choose which log file to analyze when no argument is provided:

```bash
if [[ "$#" -eq 0 ]]; then
    echo "Select a log directory:"
    select choice in logs/ /var/log/ "Enter path manually"; do
        case $choice in
            "Enter path manually") read -rp "Path: " LOG_DIR ; break ;;
            *) LOG_DIR="$choice" ; break ;;
        esac
    done
fi
```

**Lint your script with ShellCheck.** [ShellCheck](https://www.shellcheck.net/) is a static analysis tool that reads shell scripts and flags bugs, quoting mistakes, and portability issues. Paste your `logscan.sh` into the web interface and read what it reports. Almost every Bash script you write has at least one thing ShellCheck will flag.
